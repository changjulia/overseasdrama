# 外搭钩子 + 正片剧集运行手册

> 用途：本地验收、预发环境准备和故障恢复。本手册不授权生产部署。

## 1. 运行拓扑

- Web：Vinext/Node.js，读写 PocketBase，并代理外部短剧 API。
- PocketBase：持久化剧目、分集、外部素材、匹配任务、生产项目与渲染记录；JS hooks 提供队列 API。
- Python worker：处理 drama/material 队列，同时承担钩子匹配、接点精校、补充高光和 FFmpeg 渲染。
- 产物：渲染文件默认写入 `public/renders/`（可用 `LUMINA_FACTORY_RENDER_DIR` 覆盖），PocketBase 保存预览/导出 URL、SHA-256、边界台账和质检结果。

## 2. 必需依赖与环境变量

| 项 | 要求 | 缺失影响 |
|---|---|---|
| Node.js | `>=22.13.0` | Web 无法构建/启动 |
| Python | 安装 `processor/requirements-analysis.txt` | 解析 worker 无法工作 |
| FFmpeg + FFprobe | 两者均在 PATH | 抽帧、探测、渲染和质检失败 |
| PocketBase | 项目固定版本 `0.39.9` | 数据与队列 API 不可用 |
| `LUMINA_WORKER_TOKEN` | PocketBase 与 worker 完全相同 | 队列 claim/PATCH 返回 403 |
| 语义模型 Key | `DASHSCOPE_API_KEY` / `LUMINA_SEMANTIC_API_KEY` / `OPENAI_API_KEY` 三选一 | 匹配/解析任务失败 |
| `LUMINA_SEMANTIC_ENDPOINT` + `LUMINA_SEMANTIC_MODEL` | 与 Key 所在区域及供应商一致 | 模型请求失败 |
| `NEXT_PUBLIC_POCKETBASE_URL` | Web 和 worker 指向同一实例 | 前端与 worker 读写不同数据 |
| 外部数据 API | `EXTERNAL_OPEN_API_KEY` + 生产 HTTPS `EXTERNAL_OPEN_API_BASE_URL` | 月榜/播放/素材导入不可用 |
| 托管 Web → PocketBase | `POCKETBASE_URL`（仅服务端） | `/api/pocketbase/*` 网关返回 503 |
| 托管自定义 API 凭据 | `LUMINA_UI_GATEWAY_TOKEN`，Web 与 PocketBase hooks 完全相同 | 登录用户无法调用 Lumina 自定义 API |
| 托管 collection 凭据 | `LUMINA_POCKETBASE_SUPERUSER_IDENTITY` + `LUMINA_POCKETBASE_SUPERUSER_PASSWORD`（仅 Web 服务端） | 锁定 collection/file 无法经网关访问 |

本地密钥放入已忽略的 `.env.analysis.local` 或 `.analysis-worker-token`，不得写入本文档、日志或 Git。macOS/Linux 首次运行 `npm run pocketbase:start` 会以仅当前用户可读权限自动生成 `.analysis-worker-token`；如果已显式设置 `LUMINA_WORKER_TOKEN`，则将其写入该本地文件供 worker 共用。

托管模式下，浏览器只能访问同源 `/api/pocketbase/*`。该 Next 网关要求 ChatGPT 可信身份头，并在服务端换取短时 PocketBase superuser JWT 来访问已锁定的 collection/file；superuser 密码和 JWT 都不得以 `NEXT_PUBLIC_*` 暴露。自定义 Lumina API 使用独立 `LUMINA_UI_GATEWAY_TOKEN`，PocketBase 端不得设置 `LUMINA_UI_MODE=local-loopback`。建议为网关创建独立 superuser、使用密钥管理服务注入高熵凭据并建立轮换流程。ChatGPT 身份头的可信性依赖托管边缘剥离外部同名请求头，普通反向代理若不能保证这一点不得直接暴露该网关。

## 3. 上线前预检

```bash
npm run runtime:check
npm run lint
npm test
python3 -m unittest discover -s tests
```

`runtime:check` 是只读检查；失败项会以非 0 退出。PocketBase 未启动、外部 API 未配置为警告，worker 令牌、模型凭据和媒体依赖缺失为失败。

托管/预发配置需额外执行（只校验环境变量是否完整，不打印秘密）：

```bash
LUMINA_HOSTED_GATEWAY_CHECK=1 npm run runtime:check
```

## 4. 启动顺序

### Windows（当前完整 worker 监督方案）

```powershell
./scripts/start-pocketbase.ps1
./scripts/start-analysis-workers.ps1
npm run start
```

`start-analysis-workers.ps1` 监督 1 个 drama worker 与 2 个 material worker，子进程退出后 5 秒内重启。第二个 material worker 也会领取钩子匹配、接点校验、补充高光和渲染任务。

### macOS/Linux（完整 worker 监督方案）

```bash
npm run pocketbase:start
# 新终端
npm run workers:start
# 新终端
npm run dev
```

`workers:start` 默认监督 1 个 drama worker 和 2 个 material worker；子进程异常退出后默认 5 秒重启。监督器在前台运行，`Ctrl-C`/`SIGTERM` 会停止全部子 worker 并清理 PID 文件。可按实际负载选择队列：

```bash
# 只运行一个 material worker
bash scripts/start-analysis-workers.sh --worker material

# 自定义多实例与重启延迟
bash scripts/start-analysis-workers.sh \
  --worker drama --worker material:render-a --worker material:render-b \
  --restart-delay 10

# 不监督的单次调试（精确 job 不允许 queue=both）
bash scripts/start-analysis-worker.sh --queue material --once --job-id RECORD_ID
```

两个 shell 脚本都将 `.env.analysis.local` 当作数据解析，不会 `source` 执行其中命令。它们优先使用项目 `node_modules` 内固定版本的 FFmpeg/FFprobe。如果环境中的 `LUMINA_WORKER_TOKEN` 与 `.analysis-worker-token` 不一致，worker 和 macOS/Linux PocketBase 启动脚本都会拒绝启动，防止队列持续 403。

## 5. 健康检查与可观测性

- PocketBase liveness/readiness：`GET /api/health`，期望 HTTP 200 且 `code=200`。
- Worker 存活：Windows 与 macOS/Linux 监督器使用 `.analysis-worker-*.pid`；日志为 `.analysis-worker-*.stdout.log` / `.stderr.log`。shell 监督器 PID 为 `.analysis-workers-supervisor.pid`。
- Worker 就绪：不能仅看 PID。应同时确认最近的队列任务能从 `queued` 进入 `running`，且 `progress`/`lease_until` 持续更新。
- 渲染就绪：验证 `LUMINA_FACTORY_RENDER_DIR` 所指目录（默认 `public/renders/`）可写且有足够空间；渲染完成必须同时具备 `validation.passed=true`、`output_sha256`、`preview_url`。
- 建议告警：连续 worker 重启、队列最老等待时间、过期 lease 数量、失败率、剩余磁盘、模型 429/5xx 率。当前代码尚未提供独立 worker readiness/metrics HTTP 端点。

## 6. 重试与恢复

- 所有队列均使用 lease；worker 每 120 秒续租，进程崩溃后由过期 lease 重新领取。
- material 队列会区分 transient/provider/media/validation/permanent；可重试错误按 30 或 120 秒基数指数退避，上限 1800 秒。
- drama、钩子匹配、接点精校、补充高光和渲染均持久化 `error_kind` 与 `next_attempt_at`；短暂/供应商错误按 worker 计算的指数退避重领，media/validation/permanent 不会自动重试。`max_attempts` 仍是最终尝试上限。
- 仅对确认的短暂错误手工重排；不得无限重试 media/validation/permanent 错误。Windows 已有 `scripts/requeue-stale-material-jobs.ps1`，它只处理 material 队列。
- 作业完成但最终 PATCH 失败时，lease 过期后会重做作业；生产环境应监控这类重复高成本任务。

### 安全恢复顺序

1. 先停止异常 worker，保留 PocketBase 和日志。
2. 检查错误分类、attempt/max_attempts、lease_until 和模型/磁盘状态。
3. 修复凭据、网络、媒体或存储原因。
4. 重启 worker；过期 lease 将自动恢复。
5. 只对仍为 failed 且已确认可恢复的任务执行手工 retry。
6. 验证成片 SHA-256、自动质检和人工审核；不得跳过质量门禁。

## 7. 已知上线阻塞项

1. 需要为目标运行环境接入系统级守护（systemd/launchd/容器编排）；仓库内 Windows 和 macOS/Linux 监督器已提供子进程自恢复，但不代替主机级守护。
2. 需要增加 worker readiness/队列滞留监控；当前只有 PocketBase liveness 和 PID/日志。
3. 需要明确生产运行系统、持久卷、备份/恢复和密钥管理方案。
4. `EXTERNAL_OPEN_API_BASE_URL` 在生产必须使用服务方 HTTPS 地址，不能使用 README 中的 HTTP 默认值。
5. 上线前必须在目标托管边缘验证 ChatGPT 身份头由平台注入且客户端无法伪造；本地模拟身份只能验证网关契约，不能替代该平台级验收。
