# 跨设备开发交接

## 交接目标

本分支是“外搭钩子 + 正片剧集”上线准备的可恢复开发快照。当前仅用于本地开发、真实链路验收和预生产准备，不代表已达到 GO，也不包含生产部署授权。

## 另一台电脑的恢复步骤

1. 克隆 GitHub 仓库，切换到本交接分支。
2. 安装 Node.js/Python/FFmpeg/PocketBase 依赖，执行 `npm ci`。
3. 复制 `.env.analysis.example` 为本地环境文件，用安全渠道重新填入所需密钥。不要从 GitHub 恢复密钥。
4. 按 `processor/README.md`、`docs/worker队列观测.md` 和 `docs/分析环境准备.md` 启动本地 PocketBase 与 worker。
5. 执行 `scripts/runtime-check.sh` 和相关契约测试，再恢复真实分析任务。
6. 需要复用真实素材时，从已授权数据源重新入库，或通过受信私有存储转移；不要把原始剧集、用户样片或 PocketBase 运行存储提交到 GitHub。

## 通过飞书迁移本地资源

可以使用用户自己的飞书私聊/文件传输迁移下列本地资源，它们不进入 GitHub：

- 3 个原始黄金样片：`1786532318_t7aTaPzDXJ_H264_720.mp4`、`1784805656_QTi3ycwhxA_H264_720.mp4`、`1785148210_3shFMGB3nT_H264_720.mp4`。
- 如需原样恢复队列、入库 ID 和 checkpoint，私下转移本地 `pb_data/data.db` 与 `pb_data/storage/`；转移前先停止 PocketBase 和 worker，避免获得不一致快照。
- 可选转移本地验收图片、音频和原始 system snapshot；它们只用于证据复核，不是启动代码的必需项。

传输前后对同一文件执行 `shasum -a 256 <file>`，确认哈希一致。建议将数据库/媒体包和环境凭据分开传输；API Key 不放进资源压缩包，在新设备上重新配置。

## GitHub 中有意不包含的内容

- `.env*`、worker token、API Key、签名播放 URL。
- `pb_data/storage/` 的本地媒体与运行数据。
- 用户提供的 3 个原始黄金样片。
- 本地提帧图片、音频、Swift 模块缓存和运行时备份。
- 任何生产凭据、生产数据或生产发布状态。

## 恢复后的 P0 顺序

1. 确认队列租约与 checkpoint 状态，只定点续跑未完成项。
2. 完成 3 个真实钩子的 Max 精析与独立 Golden 逐字段对照。
3. 产出至少 3 组匹配，分别验证 direct cut、转场词、60–100 秒连续旁白。
4. 用真实 UI/API/worker 路径生成成片，完成 QC、人工盲评和完整功能链条矩阵。
5. 收口预生产 HTTPS、存储、监控、备份和回滚门禁；仍不执行生产部署。
