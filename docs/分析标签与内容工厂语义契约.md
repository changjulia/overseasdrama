# Lumina 分析标签与内容工厂语义契约

> 当前契约版本：`lumina-semantic-contract-v1.1`  
> 标签本体版本：`hook-ontology-v1.1`  
> 适用范围：灵感大屏、素材分析、钩子原型、人工复核、剧库分析、内容工厂、我的创作  
> 维护原则：开发变更若新增、重命名或改变字段语义，必须先更新本文的版本记录与兼容映射，再修改生产代码。

## 1. 目的与边界

内容标签用于缩小候选范围，不能代替剧情理解。完整生产判断必须同时满足三层：

1. **标签召回层**：回答候选“像不像”。
2. **语义与故事层**：回答事件“为什么发生、如何发展、由什么结果兑现”。
3. **证据与生产门禁层**：回答结论“能否回到原片、能否安全剪辑、能否进入生产”。

任何页面不得仅凭标签相似度把候选标记为“承诺已兑现”“故事完整”或“可直接生产”。

## 2. 当前代码中的标签体系

规范化入口位于 `app/lib/ontology/normalization.ts`。标签统一表示为：

```ts
type OntologyTag = {
  id: string;
  dimension: OntologyDimension;
  label: string;
  original?: string;
  confidence?: number;
};
```

### 2.1 规范维度

| 维度 | 用途 | 典型值 | 是否可独立作为生产结论 |
|---|---|---|---|
| `genre` | 题材召回 | 都市情感、狼人、复仇 | 否 |
| `theme` | 主题召回 | 身份反转、背叛、救赎 | 否 |
| `relation` | 人物关系召回 | 夫妻、继母女、上下级 | 否，必须绑定角色和时间状态 |
| `conflict` | 冲突召回 | 身份争夺、情感背叛 | 否，必须绑定事件证据 |
| `emotion` | 情绪匹配 | 委屈、愤怒、爽感 | 否，必须形成时间曲线 |
| `storyBeat` | 情节点召回 | 揭露、误会、反击、重逢 | 否，必须绑定因果阶段 |
| `audience` | 受众倾向 | 女性、熟龄、狼人题材受众 | 否 |
| `acquisition` | 买量用途 | 停滑、点击、付费卡点 | 否，属于业务目标 |

### 2.2 兼容关系

历史维度在读取时统一映射，写入与跨页面跳转只传规范维度：

| 历史维度 | 规范维度 |
| --- | --- |
| `character / characters / 人物` | `role` |
| `relationship / relationships / 关系` | `relation` |
| `plot / plots / 情节点` | `storyBeat` |
| `adUse / contentTags / 买量用途` | `acquisition` |

剧库跳转内容工厂时必须携带规范化 `ontologyTags`，包括 `code`、`dimension`、`label`、原始值、置信度、证据、覆盖集数和主次标签属性。内容工厂将这些标签用于钩子候选召回与粗排；当前阶段不设置故事匹配分数门槛，不以此阻断用户进入内容工厂。

标签比较只允许输出：

- `exact`：规范标签一致。
- `compatible`：同维度语义兼容。
- `bridgeable`：可以通过明确过渡连接。
- `contradictory`：人物身份、关系或事件存在硬冲突。
- `unknown`：证据不足。

`exact`、`compatible`、`bridgeable` 均不等于剧情承接成立。`contradictory` 是召回硬拦截；`unknown` 必须保留为待补证，不能自动当作匹配。

## 3. 四类标准语义对象

### 3.1 HookSemanticObject（钩子语义对象）

```ts
type HookSemanticObject = {
  hookId: string;
  analysisVersion: string;
  source: { materialId: string; start: number; end: number; startFrame?: number; endFrame?: number };
  event: { action: string; preconditions: string[]; result: string };
  characters: Array<{ ref: string; role: string; state?: string }>;
  relationships: Array<{ from: string; to: string; type: string; state: string }>;
  conflict: string;
  emotionCurve: Array<{ at: number; emotion: string; intensity: number }>;
  audienceQuestion: string;
  informationGap: string;
  narrativePromise: string;
  evidence: EvidenceRef[];
  safeStart: BoundaryEvidence;
  safeEnd: BoundaryEvidence;
  reviewStatus: "pending" | "approved" | "rejected";
};
```

当前映射来源：`hook_assets` 的 `themes`、`content_tags`、`relationships`、`conflict`、`emotion`、`narrative_promise`、`information_gap`、`evidence`、`safe_start`、`safe_end`。当前缺口是事件前置条件、角色状态和完整情绪曲线仍经常埋在 `analysis` JSON 中，后续应逐步结构化。

### 3.2 DramaStoryGraph（剧集故事图）

```ts
type DramaStoryGraph = {
  dramaId: string;
  analysisVersion: string;
  scope: number[];
  characters: Array<{ ref: string; goal: string; stateByEpisode: Record<string, string> }>;
  relationships: Array<{ from: string; to: string; type: string; changes: StoryStateChange[] }>;
  events: Array<{
    id: string;
    episode: number;
    start: number;
    end: number;
    phase: "setup" | "escalation" | "payoff" | "ending";
    action: string;
    preconditions: string[];
    result: string;
    unresolvedQuestions: string[];
    evidence: EvidenceRef[];
  }>;
  causalEdges: Array<{ from: string; to: string; type: "causes" | "enables" | "reveals" | "resolves" }>;
  comprehensionGaps: string[];
};
```

当前映射来源：剧目总分析、分集 `episodeSummary`、`episodePlots`、`emotionCurve`、`contentTags`，以及 `episode_highlight` 资产。当前缺口是跨集人物状态和因果边尚未作为持久化的一等对象。

### 3.3 HistoricalTemplate（历史跑量模板）

```ts
type HistoricalTemplate = {
  id: string;
  version: string;
  sourceMaterialId: string;
  sourceProjectId?: string;
  performanceEvidence: {
    platform: string;
    market: string;
    window?: string;
    spend?: number;
    impressions?: number;
    exposure?: number;
    holdRate3s?: number;
    ctr?: number;
    completionRate?: number;
    cvr?: number;
    roas?: number;
    percentile?: number;
    level: "strong" | "medium" | "weak";
    missingMetrics: string[];
  };
  hookStructure: HookSemanticObject;
  bodyStructure: Array<{ phase: string; dramaticFunction: string; duration: number; sourceRef?: EvidenceRef }>;
  connectionLogic: { hookQuestion: string; bodyAnswer: string; bridgeType: string; bridgeEvidence: EvidenceRef[] };
  timelineSkeleton: Array<{ role: "hook" | "transition" | "body" | "ending"; duration: number; purpose: string }>;
  applicability: { genres: string[]; markets: string[]; goals: string[]; contraindications: string[] };
  evidenceSnapshot: Record<string, unknown>;
  reviewStatus: "pending" | "approved" | "rejected";
};
```

曝光与跑量天数只能形成 `weak` 证据，不得单独称为“爆量”。模板进入自动推荐至少需要人工批准、可验证钩子边界和非空连接逻辑。

### 3.4 MatchTask（匹配任务）

```ts
type MatchTask = {
  strategy: "hook_to_story" | "story_to_hook" | "template_reuse";
  contractVersion: "lumina-semantic-contract-v1";
  deliveryGoal: string;
  episodeScope: number[];
  hook?: HookSemanticObject;
  storyGraph?: DramaStoryGraph;
  storyNeed?: StoryNeed;
  template?: HistoricalTemplate;
  retrievalEvidence: Array<{ candidateId: string; signals: Record<string, number>; reasons: string[] }>;
};
```

## 4. 三种生产模式契约

### 4.1 用钩子找正片：`HookPromise → StoryPayoff`

1. 分析钩子事件、关系、情绪、观众问题与承诺。
2. 标签粗召回剧集高光。
3. 用故事图验证前置条件、因果连续性和兑现事件。
4. 生成 `setup → escalation → payoff → ending` 路线。
5. 以承诺兑现、因果覆盖、理解成本、安全边界和投放目标排序。

硬门禁：真实来源、边界已验证、范围合法、无身份硬冲突、存在承诺兑现证据。

### 4.2 为正片找钩子：`StoryNeed → HookRetrieval`

1. 先形成 `StoryNeed`：核心剧情、主角目标、关系状态、因果链、理解缺口。
2. 生成 `prequel`、`background`、`parallel`、`consequence`、`amplification` 检索方向。
3. 从全部已审核外搭钩子中自动召回，而不是要求用户先选一个。
4. 对多个钩子计算理解成本降低、情绪放大、悬念强度、事实安全和连接成本。
5. 用户选择推荐钩子后进入统一故事线、过渡和时间线流程。

硬门禁：钩子不得冒充本剧事实或角色，不得造成无法兑现的承诺，必须能给出明确桥接解释。

### 4.3 复用历史模板：`TemplateStructure → DramaSubstitution`

1. 按平台、市场、题材、目标和证据等级筛选模板。
2. 冻结模板版本与效果证据快照。
3. 拆分可复用结构与不可复用故事事实。
4. 在当前故事图中寻找承担相同剧情功能的事件。
5. 输出逐项替换映射、结构保真度与不适用项。
6. 复用连接机制和时间线骨架，替换角色、事实与正片来源。

硬门禁：模板经人工批准、证据等级明确、当前剧目替换覆盖充分、无历史角色或事实泄漏、所有新片段可追溯。

## 5. 统一证据引用

```ts
type EvidenceRef = {
  sourceType: "transcript" | "ocr" | "frame" | "shot" | "audio" | "analysis" | "performance";
  sourceId: string;
  episode?: number;
  start?: number;
  end?: number;
  text?: string;
  confidence?: number;
  analysisVersion: string;
};
```

界面展示的剧情结论必须至少关联一条 `EvidenceRef`。时间统一存储为秒，界面统一格式化为“X分Y秒–X分Y秒”。

## 6. 生产门禁

### 6.1 通用硬门禁

- 来源：原始媒体存在、可播放且来源可追溯。
- 边界：钩子及正片片段起止边界已验证，对白、动作和镜头不被截断。
- 事实：角色身份、事件事实无硬冲突。
- 证据：证据引用包含有效来源ID和时间范围。

模型分、校准概率、故事完整度、承诺分、理解成本、过渡难度、目标时长和人工复核状态仅作为生产建议，不得设置为硬阻断。

### 6.2 模式专属门禁

| 模式 | 专属检查 |
|---|---|
| 钩子找正片 | `promiseFulfillment`、`causalCoverage`、`comprehensionCost` 均为建议项 |
| 正片找钩子 | `truthSafety` 属于事实硬门；`storyNeedCoverage`、`bridgeCost`、`spoilerRisk` 为建议项 |
| 历史模板 | 模板来源与证据、`factLeakage` 属于硬门；`substitutionCoverage`、`structureFidelity` 为建议项 |

## 7. 页面传递规则

页面路由或 React 状态只传实体ID、用户选择和版本指纹。后端必须按ID读取完整分析快照，禁止把页面携带的标签文本当作事实来源。

匹配上下文必须包含：

- `contractVersion`
- `ontologyVersion`
- `analysisVersion`
- `hookAnalysisVersion`
- `dramaAnalysisVersion`
- `highlightAssetVersions`
- `templateVersion`（模板模式）
- 用户选择的投放目标、剧集范围和付费范围确认

版本变化必须生成新的 `matchContextHash`，不得复用旧匹配结果。

## 8. 演进与兼容规则

1. 新增标签优先映射到现有维度；只有语义职责不同才新增维度。
2. 标签重命名必须保留 alias，禁止直接删除旧标签。
3. 新增生产字段必须定义来源、证据要求、空值语义和门禁影响。
4. 旧分析结果缺少字段时标记 `unknown`，禁止生成猜测值。
5. 模型提示词、数据库结构、TypeScript 类型和本文档必须使用同一契约版本。
6. 每个策略至少维护一组固定回归样本，验证召回、排序、证据和门禁。
