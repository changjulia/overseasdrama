# 预生产上线准备与回滚

> 适用范围：“外搭钩子 + 正片剧集”的 Web、PocketBase、分析/Match/Render worker、媒体与渲染产物。
>
> 边界：本文是预生产准备和回滚手册，不授权生产部署、迁移、推送、恢复、凭据创建/轮换或付费操作。

## 1. 当前判定

**NO-GO（截至 2026-08-31 的本地审计）**。组件级安全和可观测契约已通过一组定向测试，但还没有可以批准预生产或生产发布的运维证据链。

| 门禁 | 当前状态 | 放行条件 |
|---|---|---|
| 发布候选 | **P0 阻塞** | 冻结 commit SHA，工作区无未说明变更，可从同一 SHA 重建 |
| 运行拓扑 | **P0 阻塞** | 明确 Web、PocketBase、worker、持久卷/对象存储的目标环境、责任人和网络边界 |
| HTTPS 与凭据 | **P0 阻塞** | 预生产密钥管理器注入完整变量；所有远程上游与 PocketBase 通道使用 HTTPS/受信私网 |
| 持久媒体/成片 | **P0 阻塞** | `pb_data/storage` 与 `LUMINA_FACTORY_RENDER_DIR` 是可备份持久卷，或已实现对象存储发布；渲染 URL 可从 Web 可靠访问 |
| 备份恢复 | **P0 阻塞** | 同一时点的 DB + PocketBase storage + render output 备份已在隔离环境恢复并验证 hash |
| 迁移/回滚 | **P0 阻塞** | 带真实数据副本的前向迁移、向前修复和整快照恢复演练通过 |
| 监控告警 | **P0 阻塞** | 队列滞留、lease、失败率、worker 重启、磁盘、上游错误和备份新鲜度告警已真实投递 |
| worker 容量 | **P0 阻塞** | 按目标机型做峰值压测，证明分析/渲染不相互饿饿，并得到 p95 处理时间与积压恢复时间 |
| 自动部署 | **P0 待外部确认** | 证明主分支不会未经批准自动发生产；启用分支保护和生产环境人工批准 |

当前证据摘要见 [`release-evidence/preprod-readiness/`](../release-evidence/preprod-readiness/README.md)。

## 2. 目标拓扑和不可混用的边界

```text
公网用户
   │ HTTPS
   ▼
Web / 认证同源网关
   │ HTTPS 或同机 loopback（不向浏览器暴露 superuser/worker token）
   ▼
PocketBase ── 持久卷：data.db + storage
   ▲
   │ HTTPS 或同机 loopback + worker token
   │
Analysis / Match / Render workers ── 持久渲染卷或对象存储发布
   │ HTTPS
   └── 语义模型与外部数据接口
```

- `.openai/hosting.json` 只能证明 Web 项目与 Sites 项目关联；当前 `d1`/`r2` 均为 `null`，它不提供 PocketBase、长运行 worker 或成片持久存储。
- `scripts/start-pocketbase.sh` 固定监听 `127.0.0.1:8090`。预生产若 Web 与 PocketBase 不同机，必须另配受信 TLS/私网入口，不得改为公网明文 HTTP。
- `public/renders/` 只适合本地验收。预生产必须显式设置 `LUMINA_FACTORY_RENDER_DIR`，并让 `/renders/...` 由同一持久卷的反向代理提供，或实现对象存储发布后再保存 URL。
- Web、PocketBase 与 worker 不得共用一个全权凭据。UI gateway、PocketBase superuser、worker token、外部 API Key 和模型 Key 必须分离。

## 3. HTTPS 与 Secret 注入

| 运行面 | 必需配置 | 安全要求 |
|---|---|---|
| Web 服务端 | `POCKETBASE_URL` | HTTPS，或 Web/PocketBase 同机 loopback；浏览器统一使用同源 `/api/pocketbase` |
| Web 服务端 | `LUMINA_UI_GATEWAY_TOKEN` | 高熵独立凭据，仅 Web 和 PocketBase hook 可见 |
| Web 服务端 | `LUMINA_POCKETBASE_SUPERUSER_IDENTITY/PASSWORD` | 仅服务端注入；不得使用 `NEXT_PUBLIC_*` |
| Web 服务端 | `EXTERNAL_OPEN_API_BASE_URL/KEY` | 远程 base URL 必须 HTTPS；Key 只在服务端 |
| PocketBase | `LUMINA_WORKER_TOKEN` | 与 worker 一致，不与 UI token 共用 |
| PocketBase | `LUMINA_UI_GATEWAY_TOKEN` | 与 Web gateway 一致；预生产禁止 `LUMINA_UI_MODE=local-loopback` |
| PocketBase | `LUMINA_POCKETBASE_WORKER_BASE_URL` | HTTPS 或同机 loopback，用于签名媒体和同源下载 |
| Worker | `LUMINA_WORKER_TOKEN` | 通过密钥管理器/只读 secret file 注入，不进日志 |
| Worker | 模型 Key、`LUMINA_SEMANTIC_ENDPOINT/MODEL` | endpoint 为 HTTPS，Key 区域与 endpoint 一致；Max/Flash 路由不降低质量门禁 |
| Render worker | `LUMINA_FACTORY_RENDER_DIR` | 显式绝对路径、可写、持久、可备份；禁止依赖容器临时文件系统 |

执行规则：

1. 预生产/生产不使用仓库 `.env` 文件；由平台 secret manager 在进程启动时注入。
2. 日志只记录“已配置/未配置”、request ID、HTTP 类别和错误码；不记录 Key、Bearer token、PocketBase JWT、签名 URL 查询参数或完整上游响应。
3. 轮换流程必须能在旧/新凭据短暂重叠时完成；轮换和废止凭据属于另行授权操作。
4. 托管边缘必须删除客户伪造的 `oai-authenticated-*`、`x-forwarded-*` 和本地信任头，再注入可信身份头。本地契约测试不能替代边缘平台验收。

## 4. 对象存储、临时 URL 和 Range GET

- 全集接口返回的 URL 是有效期的输入凭据，不是长期媒体地址。必须记录 `expires_at`，在有效期内立即落盘 PocketBase，之后只使用持久化文件。
- 上游对象存储对 `HEAD` 可能返回 403。媒体健康检查必须使用 `GET` + `Range: bytes=0-0`，要求 HTTP 206 与预期 MIME；不得把 HEAD 403 当作失效。
- 完整下载必须有总超时、字节上限、重定向上限、DNS/重定向 SSRF 复检、SHA-256 与原子发布。
- **P0 缺口**：素材入库当前会把输入 `sourceUrl` 写入 `ad_materials.source_url`。若 URL 含签名查询参数，会把短时凭据持久化。上线前必须改为仅保存脱敏 origin/path 或来源 identity hash，并清理历史签名参数。
- 浏览器 `sessionStorage` 中的播放查询快照只能在当前会话使用；不得被分析 SDK、错误上报、截图或服务端日志采集。
- 当前 Web 托管配置没有 R2 binding。上线前需在“同机持久卷 + TLS 反代”和“对象存储 + 服务端签名访问”中明确选一条可恢复路线。

## 5. PocketBase 数据与媒体备份/恢复

### 5.1 备份必须是同一时点

备份单元包含：

1. `pb_data/data.db` 的 SQLite 一致快照（不得在活跃 WAL 上直接拷贝主文件）。
2. `pb_data/storage/` 及 `.attrs`；只备份 DB 会留下无法播放的文件引用。
3. `LUMINA_FACTORY_RENDER_DIR` 中所有成片；PocketBase 只保存 URL/SHA，不代表文件已备份。
4. 发布 commit SHA、PocketBase 版本、已应用迁移最大版本、各集合记录数、文件数/字节数和每个备份件的 SHA-256 manifest。

备份顺序：进入维护窗口 → 停止新建任务/上传 → 停 worker 并等待活跃 lease 清零 → 生成 DB 一致快照 → 备份 storage/render → 生成 manifest → 再允许变更。

### 5.2 恢复演练验收

恢复只能在隔离目录/隔离实例进行，不得覆盖当前运行数据。证据必须包含：

- `PRAGMA quick_check` 和 `integrity_check` 通过；迁移版本与备份 manifest 一致。
- 集合记录数、存储文件数/字节数与 manifest 一致；无孤儿引用和缺失文件。
- 分层抽样剧集、素材、旁白和成片，验证 Range 播放、文件 SHA、音视频探测和对应 PocketBase 血缘。
- 用恢复实例完成一条不产生付费请求的读取/预览链路。
- 记录实际 RPO/RTO、恢复操作人和独立复核人。RPO/RTO 没有业务批准前不得自行承诺。

仓库内 `release-evidence/2026-08-30/pre-local-runtime-backup/` 是旧的本地保护，不是当前迁移版本的预生产恢复证据。

## 6. 队列、监控和告警

`scripts/check-worker-queues.sh` 是只读瞬时快照，不是监控系统。预生产至少每 60 秒采集并保留以下信号：

| 信号 | 预警/严重建议值 | 处置 |
|---|---|---|
| PocketBase `/api/health` | 2 次连续失败 / 5 分钟不可用 | 禁止新任务，保留日志和快照，不自动迁移 |
| 各队列最老 queued 时长 | 超过该队列 SLO 的 50% / 100% | 检查 worker 容量、上游限流和磁盘 |
| `lease_expired` | >0 立即预警，连续 2 个周期严重 | 按 job ID 检查心跳/进程，不批量无限重试 |
| `backoff_due` / `attempt_exhausted` | >0 预警 / 任何 exhausted 严重 | 按 provider/media/validation/permanent 分类处理 |
| worker 心跳/重启 | 5 分钟无心跳 / 15 分钟重启≥3 | 停止同 lane 新任务，保留 stderr |
| 队列失败率 | 15 分钟 >5% / >15% | 按模型 429/5xx、媒体、QC 分开告警 |
| 磁盘 | <20 GiB 或 <15% / <10 GiB 或 <8% | 暂停新渲染与媒体入库，禁止盲删数据 |
| 备份新鲜度 | 超过批准 RPO | 禁止发布 |

告警验收不是“配了规则”，而是在隔离预发中注入一次过期 lease、失败任务和磁盘阈值模拟，证明真实通知渠道收到、恢复后自动关闭。

## 7. Worker 容量与隔离

当前默认监督器启动 1 个 drama worker 和 2 个 material worker。material worker 还会领取 hook match、entry precision、supplemental highlight 和 render，因此“有两个进程”不能证明渲染不会饿饿语义任务。

上线前容量证据必须记录：

- 目标机型 CPU/RAM/GPU、本地/网络磁盘 IOPS/带宽、上游模型 QPS/并发限制。
- 单个 coarse/detail/precision/material/match/render 的 p50/p95 耗时、峰值内存、临时盘占用和模型请求数。
- 用固定 10 集剧集、多题材素材和至少 3 个并发真实渲染进行压测；不用空队列/合成空任务代替。
- 暂停、worker 崩溃、上游 429、网络中断和磁盘接近阈值时的积压恢复时间。
- 若无法在配置上为 render 预留独立 lane，必须把“渲染不会拖垮分析/Match SLO”作为 P0 压测门禁。

## 8. 迁移与发布顺序

当前迁移审计结论是**备份后只向前升级**。多个 `down` 会删除集合/字段/文件、收紧枚举或重新开放匿名规则，不可作为默认回滚。

未经另行部署授权时，以下只是执行顺序，不是当前操作命令：

1. 固定 release SHA 和可重现构建产物；记录 Node/Python/PocketBase/FFmpeg 版本和 lockfile hash。
2. 在隔离的真实数据副本上执行全部迁移；比对 schema hash、集合数量、唯一索引冲突和媒体一致性。
3. 先上能同时读新旧可选字段的 Web/gateway reader，再停旧 worker、冻结写入、制作同时点快照。
4. 升级 PocketBase/schema。`1787570800_lock_hosted_collections` 必须与认证 gateway 可用性验证同批完成，不允许通过 migration down 重新开放匿名集合。
5. 只启动单个每类 worker 作为 canary，验证 lease/心跳/持久化/QC，再扩容到已验证的并发数。
6. 验证 Web 同源 gateway、读写白名单、身份头防伪造、媒体 Range 和渲染回放，再开放新任务。

## 9. 回滚分类

| 故障类型 | 默认策略 | 禁止动作 |
|---|---|---|
| Web/UI 回归，schema 未变 | 将 Web 回到上一个已验证产物，PocketBase/worker 保持不动 | 不因 UI 故障执行 DB down |
| Worker 回归 | 停新 claim，等待/终止 canary lease，回到兼容 worker 产物；保留失败记录 | 不清空 attempt/error/QC，不无限 retry |
| 上游模型/外部 API 故障 | 暂停相关入库/分析 lane，保留队列和 backoff；恢复后 canary | 不降低证据、人工审核或付费范围门禁 |
| 迁移/schema 故障，无业务写入 | 优先新的 forward-fix；若已批准，整体恢复迁移前同时点快照 | 不单独恢复 DB，不盲目 migration down |
| 迁移后已有业务写入 | 立即冻结写入，保全当前故障快照，由业务责任人决定 forward-fix 或接受 RPO 的整快照恢复 | 不自行丢弃迁移后数据 |
| 凭据疑似泄漏 | 停用相关入口、封存日志、由授权人轮换/废止并检查访问记录 | 不在工单/对话中复制 Key，不由自动化自行创建凭据 |
| 媒体/成片损坏 | 冻结删除和新渲染，根据 manifest 整体恢复 storage/render，复核 DB 引用和 SHA | 不仅修改 URL 或跳过 QC |

回滚完成后必须再跑第 10 节所有核验，并将故障快照、恢复快照、文件 hash、队列变化和人工结论关联到同一 incident ID。

## 10. 发布前后核验

### 发布前

- [ ] `bash scripts/preprod-readiness-check.sh` 返回 0，且所有 attestation 由独立复核人签字。
- [ ] `npm audit --omit=dev --audit-level=high`、定向安全契约、Python 媒体/故障注入测试通过。
- [ ] release SHA 冻结，lockfile 与构建产物 hash 已记录；当前分支推送不会绕过生产批准。
- [ ] 队列无 queued/active/expired lease，或已有明确且已批准的保留清单。
- [ ] 同时点备份与恢复演练在 RPO 内；磁盘高于预警阈值。
- [ ] 读取权限、版权/付费范围、过渡审批、QC 和人工审核门禁未被降低。

### 发布后（canary 窗口）

- [ ] PocketBase health 200；未认证访问 collection/file 失败，认证同源 gateway 白名单路由成功。
- [ ] 服务端外部 API 通过 HTTPS 返回；一字节 Range GET 返回 206，完整下载后改用 PocketBase 持久文件。
- [ ] 每类队列的 canary 从 queued 到 active 再到 succeeded/failed，progress、heartbeat、lease、error_kind 和 backoff 符合预期。
- [ ] 一条真实分析与一条真实渲染产出可追溯结果；成片 `validation.passed=true`、SHA-256 一致、Range/完整播放成功。
- [ ] 过渡未审批、权利未确认、媒体损坏和 QC 失败仍然 fail closed。
- [ ] 监控有新数据，告警测试消息被收到；日志中无 Key/JWT/签名 URL。
- [ ] 检查返回内容质量，不仅检查 HTTP 200、字段非空或任务 succeeded。

## 11. 自动部署风险

- 仓库当前有 `.openai/hosting.json` 和 Sites/Vite 插件，并且处于 `main` 分支。本地没有 `.github/workflows`，但这不能证明 GitHub/Sites 控制面没有主分支自动发布。
- 未得到 `deployment-policy.json` 证据前，**不得 push main，不得运行 Sites/Wrangler 发布命令**。
- 证据必须包含：生产分支规则、必需审批人、自动部署开关状态、可见的目标环境名称、回退到上一产物的平台流程和一次非生产演练。
