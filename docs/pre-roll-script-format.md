# 前贴故事线与提示词脚本

入口：内容工厂 → 外搭钩子 → 第四种工作流「前贴脚本」。三步为：选择剧目与高光 → 选择正片故事线 → 生成买量钩子与脚本。此入口不触发外部素材匹配或视频渲染。

买量钩子走向支持欺压反杀、身份反差、背叛复仇、危险救援、关系悬念；可多选，不选则自动匹配。只选一种时仍生成三个不同首屏事件或信息安排的方案。生成以具体观看期待为起点，呈现首屏事件、情绪升级、局势转折、卡点和正片承接。观看期待与转折随候选返回，在方案卡和 Markdown 下载中保留。

先尝试生成三个前贴故事线方向，逐条复核后保留合格候选，再为选中方向生成制作脚本；不足三个时显示实际可用数量，不拿无依据的候选凑数。输入包含所选故事线、片段高光来源、当前选择的正片切入点、剧情理解、禁止揭露的信息、对白语言、画幅和时长。改变输入后旧记录仍可查看，生成新方向会另存一轮；可重新生成，取消请求，复制整篇、逐镜复制或下载 Markdown。生成记录和创作设置自动保存到当前浏览器；返回前贴脚本页面后可从历史选择器恢复，无需重新生成故事线。

## 从 scriptai 学习的规范

来源：`scriptai/server/flowerGamePrompts.ts` 的 `flowerScriptFormatInstruction` 与 `buildDisplayProductionScriptFormatBlock`，以及 `scriptai/server/geminiBackend.ts` 的格式校验逻辑。

- 固定章节顺序：【基本要求】→【分镜脚本】→【分镜标签】，无开场白。
- 基本要求必须完整列出风格、主要场景、情绪氛围；短剧补充人物一致性、连续性、画幅、对白语言、时长。
- 每个分镜独立成段，以 `[MM:SS-MM:SS]` 开头，从零连续到目标时长。
- 使用所选说明语言的剧情分镜叙述，景别、运镜、动作、表情及声音融入句子；不使用视频拆解的分号字段清单。
- 台词存储在独立 dialogue 数组，包含 speaker、text、可选 subtitle；导出时使用「」显示。说明、对白、字幕语言在前贴工作台分别设置，默认继承工厂对白语言；界面保持中文。
- 标签包含核心冲突、情绪、景别、运镜、画面、动作、配音和核心卖点。卖点换为短剧观看动机，不继承游戏题材约束。

## 短剧适配

### 人物一致性与实际参考素材

「前贴脚本」新增人物一致性面板，从剧情理解的 canonicalCharacters 初始化固定角色 ID；可修改姓名、别称、身份、关系、外观与声音，并添加前贴原创角色。正片视频支持定位接点、暂停截图和按百分比裁切；也可上传 JPG／PNG／WebP。参考图分为正脸、侧脸、半身／全身和接点状态，每个角色最多六张。图片写入本机浏览器 IndexedDB，文字历史只保存图片 ID 和来源集数、秒数。

正片接点状态覆盖服装、物品、伤势、情绪、位置与已知信息，按故事线、接点和分析版本隔离。分镜输出 characterStates，绑定固定角色及每镜起止状态；未知角色、说话人物未绑定、无说明的跨镜状态变化会被修复。模型复核检查人物语义与正片接点相容性，不声称已读取参考图像素或完成人脸视觉核验。

完整提示词和逐镜提示词携带对应角色参考文件与状态，逐镜导出时间归零。ZIP 包包含实际 JPG、script.txt、shots/*.txt 和 manifest.json（角色卡、原片来源、逐镜绑定）；图片丢失会明确提示。缺少外观图或接点信息仍可创作，但会列出待补充项，不能称作已完成视觉一致性验证。

角色包随每轮生成记录保存；可用“按当前角色包另存并重生成脚本”为已有方案补上人物约束，原记录不覆盖。修改当前角色或移除参考图不改变历史快照。使用视频模型时需把 ZIP 内对应图片实际上传并绑定角色；本功能不自动提交视频生成，也不代替对生成结果的视觉核对。

创作定位是以现有正片故事线为后续承接锚点，向前续写新的买量钩子故事。允许原创前置事件、冲突、阻碍、道具互动、对白和新的前因，候选用 inventedDetails 记录，分镜补写用 continuity 说明。分镜阶段保留已选钩子的核心方向，可继续补写必要情节使故事成立。

生成与复核共同使用 `PRE_ROLL_PREQUEL_POLICY`。原片未交代的内容属于创作空间，不因“缺少对应镜头”或“新增因果”否定；复核关注新增前贴是否与正片明确矛盾、是否自然导向正片入口，以及主要观看期待能否由正片推进。正片不需要再次证明前贴所有原创事件。

候选展示首三秒、递进、末镜悬念、正片兑现、吸引力假设、创作增补；引用片段索引必须有效。脚本显示与正片首镜的承接方式和生成前需要准备的参考素材。逐镜复制保留共用约束并将该镜时间归零。不调用 Seedance API，也不声称完成视频生成或经过投放验证。

服务端使用现有语义模型配置：`LUMINA_SEMANTIC_ENDPOINT`、`LUMINA_SEMANTIC_MODEL`、`LUMINA_SEMANTIC_API_KEY`（或 `DASHSCOPE_API_KEY` / `OPENAI_API_KEY`）。可用 `LUMINA_PREROLL_MODEL` 单独指定脚本模型，避免影响原有视频分析。支持现有 Chat Completions 和 Responses 协议。生产部署将配置注入前端服务的服务端运行环境；密钥不发送到浏览器。开发本机使用同源请求，其他环境沿用 ChatGPT 身份校验。

格式由结构化结果渲染，校验连续时间、总时长、必要字段和证据索引。语言仅检查对白及字幕字段，中文说明不触发英语对白错误。支持 18 个语言/地区选项；本地只拦截高置信度文字体系错配，独立模型复核处理同字母体系语言、语义和剧情。专名、感叹词及不确定短文本不单独阻断；用户可显式启用混合对白。

候选分别校验与复核，每个失败候选最多修复两次；合格方向不重写。对白修复只应用 dialogue，保留动作、时间和剧情字段，已通过本地语言检查的对白在定点修复时保持原值。修复后再复核完整候选。创意强度、慢开场、反差不足为建议，不作为硬性否决。明确事实冲突、受保护内容泄露和语言错误才阻断。

API 返回 validation.status（complete/partial/failed）、repairs、rejected 和 warnings。部分成功保留可用方向并允许继续生成脚本。补生成请求携带 count 与 existingIdeas，只追加缺少的方向，不清空已有脚本。全部失败、脚本失败或重新生成失败均保留已有结果；页面区分方向与具体方案脚本错误。取消请求不进入重试。

兼容旧版 narrative 内「对白」及未提供语言扩展字段的上下文。新生成默认使用结构化对白。模型复核不等同原片人工事实审核；未知外观和空间细节仍需参考素材确认。


## 批量生成与浏览器缓存

方案支持多选、全选、只生成缺失脚本、重新生成所选、重试未完成。批量最多并发两项，逐项展示排队、生成中、已保存或失败状态，每项结束立即写入 localStorage。单项失败不会影响同批其他项；重新生成失败时保留该方案原有脚本。

工作区使用 `lumina.pre-roll.workspace.v1:<剧名>` 分剧保存创作参数、每轮完整上下文、候选、选择项、脚本和任务状态。历史生成使用该轮保存的上下文，晚返回结果不会覆盖用户切换到的新记录。缓存存储在当前浏览器，不承诺跨设备同步；空间不足或浏览器禁用存储时显示自动保存失败并提示下载，内存中的结果仍可使用。

生成队列独立于 React 组件：站内导航卸载页面不会取消批次。刷新或关闭浏览器会中断未完成请求；恢复时标记为中断，用户可重试，已完成脚本保留。历史入口在进入前贴流程后即显示，不要求重新走完正片选择步骤。

各工作区共用 `globals.css` 的 `--lumina-*` 主题变量，统一主蓝色、交互态、浅色背景、正文和次级文字、边框；前贴卡片、按钮和输出区使用相同圆角与全站字体尺度。
