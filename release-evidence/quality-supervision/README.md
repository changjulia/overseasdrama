# 全链路工程监督与内容质量管理

本目录属于独立监督面，和被测系统实现隔离。监督者只产出评测协议、冻结后的专家标准答案、系统对照、差距报告与复测记录；不得修改生产代码、提示词或系统答案。

## 双轨顺序（不可逆）

1. 登记真实输入的不可变指纹，并记录监督者可见的信息边界。
2. 在读取被测系统答案前，由监督者像“理想系统”一样独立分析，产出 `golden`。
3. 校验 schema、写入 `frozenAt`/`goldenVersion`/文件 SHA-256，并将状态改为 `frozen_blind`。
4. 冻结之后才允许读取系统输出。原 golden 不覆盖；纠错必须新建版本并解释原因。
5. 逐字段、逐时间码、逐人物关系和逐因果链对照，评分并执行硬门禁。
6. 每项差距进入缺陷台账：严重度、责任模块、复现样例、验收断言、回归测试建议。
7. 实现 Agent 修复；监督者使用同一 case 重跑并记录系统版本，直到阈值满足。

## 防止自证

- 监督者不得让系统输出参与 golden 的生成或补全。
- 缺少原剧片源、制作血缘或系统输出时，明确标记 `pending` / `not_evaluable`，不得猜测。
- 人工指定的业务先验（例如“这是外搭正例”）与媒体中可观察事实分栏记录。
- 监督者不提交被测实现改动；建议只能写在差距报告。
- 任何冻结后的 golden 改动必须提升版本号，旧版永久保留，并记录变更原因和批准者。
- `frozen_with_prior` 表示当前系统答案未读取，但评测者接触过可能影响内容判断的旧分析先验；该版本只能作探索性基线，不能进入严格盲评指标分母。

## 评分与上线判定

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 事实/证据准确性 | 25 | 人物、关系、剧情事实、证据时间码是否真实且不越界 |
| 高光定位质量 | 15 | 高光是否完整、边界安全、可直接制作 |
| 钩子留人力 | 15 | 停滑句、冲突升级、悬念与信息密度 |
| 故事完整性 | 15 | 起因、关系、冲突、结果/悬念是否可理解 |
| 钩子-正片匹配 | 15 | 叙事承诺能否被正片承接，是否误导或严重剧透 |
| 转场/解说自然度 | 10 | 时空/人物/因果桥接、文字可读、旁白和原声协调 |
| 工程可靠性 | 5 | 入库、状态、持久化、重试、渲染、QC、审核、导出 |

总分为七维加权分（0–100）。总分不能抵消硬门禁。以下任一项出现即 `NO-GO`：

- 关键人物、关系或剧情事实错误；
- 引用的证据不存在或时间码越界；
- 未批准资产进入成片；
- 故事严重断裂。

首轮推荐门槛同时适用：故事完整度 ≥80、钩子留人 ≥80、承诺兑现 ≥75、连通性 ≥70；严重事实冲突/虚假承诺必须为 0。数据集级指标与分题材指标沿用上线推进文档阈值。

## 产物

- `protocol.schema.json`：冻结 golden 与对照结果的机器可读 schema。
- `scoring-rubric.md`：逐维评分锚点和时间码容差。
- `case-ledger.csv`：从输入到复测的可追踪台账。
- `gap-report-template.md`：差距到开发与回归的转换模板。
- `baseline-v1.md`：本轮基线与缺失证据。
- `artifacts/quality-golden/<case_id>/golden-vN.json`：冻结的专家标准答案。
